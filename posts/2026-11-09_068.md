# 一个人，五周，一个 GUI 框架：22 个新项目的清单，和 star 最高的三个

> 9 月底到 11 月初，GitHub 上冒出一批不太好归类的项目：一个五周写出来的 Go 桌面 GUI 框架、一个把 AGENTS.md 当产品契约、让 AI 通过 adb 逐个拨开关的安卓去广告工具、一个把 26B 模型塞进 2GB 内存的推理引擎，还有一个用纯 Rust 从零重写的 Photoshop 式图像编辑器。它们既不是新模型，也不是新的 Agent 框架，共同点却很一致：过去需要一个团队、一年半载才敢碰的东西，现在一个人带着几个 Agent，几周就能推到能用的状态；而做出来的东西，又反过来把 Agent 当成一等用户来设计。这回我把检索范围铺开，凑了一份 22 个项目的清单，按 star 从多到少排好，先给全貌和逐个简介，再挑 star 最高的三个细看。

*清单口径：2026 年 1 月 1 日之后建仓、我逐一读过 README 或核心文档、且与「AI 把开发/做事门槛压平」直接相关的工具型仓库；纯文档/教程/规范集合、以及 2025 年及更早建仓的老仓库不计入。star 与建仓日期取自 GitHub API 的 2026 年 11 月 9 日快照——star 是注意力，不是质量评分。除文中注明外，我没有在真机或生产环境逐一复现，效果以各项目官方文档为准。*

## 三、star 最高的三个，逐个细看

### 1. storytold/photocraft · 78,031★

**它是什么。** 一个用纯 Rust、clean-room 方式从零重写的 Photoshop 式图像编辑器：69 个工具、16 种调整图层、图层蒙版与矢量、真 PSD/PSB 读写、wgpu（Metal / Vulkan / DX12 / WebGPU）GPU 合成、copy-on-write 瓦片，24 个 crate、1,700 多个测试，整套引擎和 UI 还能编译成 WebAssembly 跑在浏览器里。PSD 支持是照 Adobe 公开规范单独写的 crate，psd-tools 测试集 309 个文件里，重存后渲染一致的有 307 个。

**AI 到底省了哪一步。** 这类软件过去是「Adobe 级别团队 + 十几年积累」的代名词，现在一个小团队敢从零重写，本身就是门槛塌陷的样本。但更值得看的是它的架构选择：**每个菜单项、工具和对话框都走同一张 500+ 命令的注册表，UI、CLI、JSON 控制通道和 MCP server 调的是同一套命令**——用 README 的话说，"anything you can click, a script or an AI agent can do too"。README 里每一张截图，都是通过 loopback 控制通道离屏渲染出来的；仓库根目录的 `AGENTS.md` 开头就写着给「新贡献者和 AI agent」看。也就是说，它不是「用 AI 写完之后再补个接口」，而是从第一天就把「被 Agent 驱动」当成一等需求。

```bash
photocraft-cli run wave.psd \
  --cmd filter.sharpen.smartSharpen     --params '{"amount":80}' \
  --cmd layer.newAdjustmentLayer.curves --params '{"points":[[0,0],[64,48],[192,212],[255,255]]}' \
  --out wave-final.png
photocraft-cli mcp        # 让 Agent 通过 MCP 驱动同一个引擎
```

**边界。** 项目自己写得很直白：early alpha，**不是 Photoshop 日常专业工作的替代品**，最大缺口是 AI / 生成式功能、15 个未实现的工具、排版深度和插件兼容。还有一句特别诚实的话：每个 Photoshop 菜单项都接到了命令，但 `parity-checklist.md` 量的是「接没接上」，不是「行为对不对」。star 第一，不等于能用它交活。

### 2. pingdotgg/t3code · 52,804★

**它是什么。** README 第一句给的身份是 "agent harness control surface"：把本机已经装好、已经登录的 coding agent 收进一个界面，用 iOS / Android App、Web 或 Electron 桌面端远程操控。支持 Claude Code、Codex、Cursor、Grok Build、OpenCode、Google Antigravity 和 fx。装起来是一行命令：

```bash
curl -fsSL https://t3.codes/install.sh | sh
t3                    # 起服务并打开本地 Web App
t3 service install    # 常驻后台
```

**为什么是它涨得最猛。** 11 月第一周它涨了 15,379 星、总数 52,394，坐上周榜第一，而版本号还是 0.1.8 nightly。11 月 8 日一天发了两个 nightly：定时任务可以挪到另一个对话线程而不丢历史、界面里能直接更新用 mise 安装的 agent——更新全集中在「调度」和「线程管理」，没有一条是关于模型能力的。这跟我在[《从「用 Agent」到「管 Agent」》](#post-067)里记的判断对上了：单任务的上限取决于模型，多任务的上限取决于人的注意力；一个月前大家比的是哪个 agent 更聪明，这周星数流向的是「怎么同时管好几个 agent」。

**AI 省了哪一步。** 它不替你写代码，省的是「人盯着」的成本：出门在外用手机接着推进本机上的会话，实际干活的还是你那台开着的电脑。README 里那句 "Wait, what are you selling me?" 的回答也挺有意思——Nothing，作者只是想要一个够快、能远程、且真正开源的外壳，并明确说「如果我们走错方向，你拿着全部东西 fork 出去做自己想要的编辑器」。

**边界。** 作者自己加粗写了 "We are very very early in this project. Expect bugs."，目前基本不接受大贡献；桌面端和服务器要保持版本同步；远程访问要自己配；前提是本机常开、对应 CLI 已安装并登录。nightly 阶段的界面和数据格式变化快，别急着把它焊进团队流程。

### 3. Nutlope/hallmark · 51,139★

**它是什么。** Together AI 做的设计 Skill，目标写得很直接：**拒绝看起来像 AI 生成的页面**。它从 50 个主题里抽 3 个（主题是「材料」——纸张、字体、颜色、表面与纹理，不是模板，所以同一个主题接到两个需求会产出两个不同的页面），按这个页面要办的事来布局：预订页就预订、商店就卖货、订阅页就订阅，动作放在该放的位置。然后用 `sloplint` 在真实浏览器的 8 个宽度上检查，最后交给一个上下文干净的子 Agent 冷眼复审。

它把「AI 味」列成了具体的可检查项：每个标题上方都挂 eyebrow、全大写的字距标签、标题里恰好一个彩色词、一页空框或全是照片、hero 没占满屏、每页结尾都是邮件订阅、表单说「谢谢」但其实没发送。门禁分三层：

- **Floor**：绝不上线——对比度、焦点、reduced motion、虚构事实、手机布局坏掉；
- **Reflex**：模型默认会掉进去的习惯，有理由可以记录在案地推翻；
- **Finish**：工艺细节，永远不挡发布。

```bash
npx skills add nutlope/hallmark -g     # -g 装到所有项目
/hallmark redesign ./src/app           # 保留内容与接线，重做系统
/hallmark audit ./index.html           # 只报告，不改
node skills/hallmark/scripts/sloplint.mjs <file-or-dir> --render
```

`redesign` 之前会先 `sloplint --before` 记下每条链接、字段、事件和标题，`--kept` 发现少一个就让重做失败——**改版不能把功能改丢**，这比「生成得更好看」实在得多。

**AI 省了哪一步。** 当「做出一个页面」的成本趋近于零，稀缺的就变成了「这个页面能不能见人」。hallmark 的取巧之处在于没有再去训一个审美模型，而是把品味写成主题文件、确定性 lint 和一道人工可干预的门禁。同一时期冒出来的 `pbakaus/impeccable`、`Leonxlnx/taste-skill`、`heydamir/unslop` 都在补同一个缺口，说明这不是个别需求，是 vibe coding 普及后的系统性副作用。

**边界。** 它是 Skill，不是设计系统，别指望它统一全公司视觉；需要 Node 18+，浏览器检查还得装 `puppeteer-core` 和 Chrome（缺了静态检查仍能跑）；它管的是「AI 味」和基本可用性，替代不了品牌规范与真实的设计评审。

## 四、把这 22 个项目叠在一起看

![同一个仓库，两类读者：AI 时代的开源项目多了给 Agent 看的一层](images/post-068/two-readers.svg)

### 1. 仓库的一等读者变了

传统开源仓库的目录围绕「人」组织：README、docs、Releases、截图。这批仓库多了一层平行结构——**AGENTS.md / SKILL.md / 给 Agent 的 CLI / 随版本发布的 skills 命令**。`android-ad-cleaner` 根目录同时躺着 AGENTS.md、CLAUDE.md、CODEBUDDY.md、CONTEXT.md、CODING_STANDARDS.md，给不同 Agent 各写一份；`mygo` 的原生模板自动塞一份 `.agents/skills/mygo-maintenance/SKILL.md`；`agent-browser` 用 `skills get core` 让说明永远匹配已安装的 CLI；`photocraft` 干脆把 500+ 命令同时暴露给 UI、CLI 和 MCP。

影响比「文档变多了」深得多：当 Agent 是读者，**文档里的模糊地带会直接变成线上的误操作**。`android-ad-cleaner` 的 11 条硬规则里才有「每条 adb 都带 `-s <序列号>`」「保护类开关要打开而不是关掉」「`com.opos.ads` 可以挂、下拉搜索和负一屏的包绝对不挂」这种啰嗦到极点条款。写给人时一句「小心别关错」就够了，写给 Agent 就得把反例一条条列出来。

### 2. 迭代单位从「版本」变成了「天」

`mygo` 五周 944 次提交；`android-ad-cleaner` 两周 974 次提交、11 月 9 日当天还在发 v0.4.1；`t3code` 一天两个 nightly。更值得注意的是它们**记录失败的方式**：`android-ad-cleaner` 的 README 写着「OPPO Find X9 Ultra 八段整轮 211 秒、回读确认 173 项」「小米 18 Pro Max 从 150 秒优化到 97 秒」，也写着「本仓库未复跑」「退出码 1 只因负一屏段读不到轮播单选」「天气提醒重要级别从 4 变为 3，原因未确认」。当发版成本低到以天计，「可信」不再来自「我们测试充分」这种结论，而来自把实验记录原样摊开。

### 3. 门槛没有消失，只是换了位置

AI 把**「会不会写」**压得很低：Go 的自绘 UI、Swift 的 Metal kernel、Rust 的图像编辑器、给每台机型写的脚本，都能被快速产出来。但这些项目真正花心思的地方全在另一头：

- 什么**不该**动——`android-ad-cleaner` 不 root、不 `pm uninstall`、不替用户同意协议、不截账号页；`craft-anything` 默认 Clean room，不读原作代码，声明不绕过 DRM；
- 怎么确认**真的**动对了——每步回读、复跑幂等、「仍开着: 0 个」、`sloplint` 八种宽度、`photocraft` 用 CPU 合成器当 GPU 合成器的 oracle；
- 出错怎么**退回去**——快照、`unsuspend`、`--kept` 检查、可还原命令；
- 什么时候**停下来问人**——改之前说清楚、approval 卡片、拿不准的渠道问用户、`agent-autoloop` 只在关键节点发卡片。

我在[《想干票大的：AI 时代，独立开发者最后都成了范德彪》](#post-061)里写过 AI 降的是工具门槛、不是「把事情做成」的门槛。这批项目是个更具体的注脚：**它们之所以好用，不是因为 AI 写得多，而是因为作者把「不许做什么」写得足够细。**

### 4. 以前「不划算」的长尾，突然划算了

给 50 多个机型各写一份脚本、给每个 App 逐个分辨通知渠道、给每个工具写一份 SKILL.md、给每个 Agent 一份独立 worktree、给设计稿准备 50 套主题——这些都是典型的「技术上行得通、经济上不值得」的活。AI 把边际成本压下来之后，长尾突然变成了产品本身，甚至变成社区贡献的入口：贡献者用自己的手机跑一遍 `adapt survey / explore / gen / check`，就能给 `android-ad-cleaner` 提一份机型脚本 PR。**新项目不一定是新品类，很多只是把过去被成本挡在门外的细活做完了。**

### 5. star 是注意力，不是成熟度

这份清单按 star 排序，但榜单本身就是个提醒：star 第一的 `photocraft` 自己标着 early alpha 并明说「不是 Photoshop 替代品」，第二的 `t3code` 写「very very early, expect bugs」，第六的 `craft-anything` 也是 early alpha；倒是排在第 17、18 位的 `android-ad-cleaner` 和 `mygo`，一个把每台机的失败记录摊在首页，一个把 944 次提交留在 git 历史里。星数衡量的是这一周有多少人点了一下，衡量不了它能不能进生产。

## 五、想上手，从哪儿开始

| 你想试什么 | 起点 | 成本 / 前提 |
| --- | --- | --- |
| 看看专业桌面软件能被 Agent 驱动成什么样 | `photocraft-cli run ... --cmd`，或 `photocraft-cli mcp` | Rust 1.97+；early alpha，别拿它替代日常工具 |
| 出门也能管本机 Agent | `curl -fsSL https://t3.codes/install.sh \| sh` → `t3` | 本机常开、对应 CLI 已登录；nightly，界面会变 |
| 给 Agent 生成的页面加一道设计关 | `npx skills add nutlope/hallmark -g` | Node 18+；浏览器检查另需 puppeteer-core 与 Chrome |
| 写个 Go 桌面小工具 | `bunx mygo-cli init` 或 `-template native` | Go 1.27.3+；原生模板不需要 Node / Bun |
| 让 Agent 自己测自己的 UI | `mygo-automation skills` 打印当前版本 SKILL.md | 仅开发构建可用，生产构建会裁掉 |
| 给安卓去广告 | 桌面客户端，或把 README 里那段提示词丢给本地 Agent | 数据线 + USB 调试；先备份、留还原命令、用完关开发者模式 |
| 在 8GB Mac 上跑 26B | `swift build -c release` | macOS 26 / Metal 4 / Swift 6.2+；首次下载约 15GB |
| 给 Agent 一双能看页面的眼睛 | `agent-browser snapshot -i` → `click @e1` | `npm i -g agent-browser`；页面变化后必须重新 snapshot |
| 并行跑多个 Agent 不打架 | `wt switch` / `wt list` / `wt merge` | 商用前确认许可证 |

三条提醒：

1. **别把 star 当成熟度。** 榜单里最年轻的才几天大，`t3code` 还在 0.1.8 nightly，`mygo` 是 0.8.x，`android-ad-cleaner` 几乎一天一版且明确说客户端「不会自动更新」。
2. **越「能自动动手」的工具，越要先看它写了哪些「不动手」。** 先读 AGENTS.md、硬规则和还原说明，再决定要不要让它连上你的设备或代码库。
3. **从只读命令起步。** `check`、`snapshot`、`chan-scan`、`audit`、`adapt survey` 这些只读入口是白送的：先看它怎么描述你的环境，再决定要不要执行。

## 六、结语

这 22 个项目里没有一个是靠「更聪明的模型」赢的。它们赢在把 AI 放进了两个位置：**生产端**，一个人带着一群 Agent 去碰过去不敢碰的工程规模；**消费端**，把 Agent 当成需要契约、需要工具、需要验证的一等用户来设计。中间那份「人写的规则」——哪些开关不能碰、哪一步必须回读、什么时候停下来问一句——反而成了最值钱的部分。

门槛确实被压平了，但压平的是「开始」这一下。后面那段「做对、兜住、长期维护」，还是得人自己走完。
