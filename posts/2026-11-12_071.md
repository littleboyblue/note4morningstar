# Token 越烧越多，利润却没涨，为什么

> 周一早上，两张报表同时摆在桌上。第一张来自 AI 平台：过去一年 token 消耗涨了 6 倍，调用次数涨了 4 倍。第二张来自财务：收入涨了 18%，毛利率掉了 5 个点，净利润几乎没动。老板问了一个很难回答的问题：钱到底花在哪了？这个问题难，不是因为答案复杂，而是因为 token 和利润之间，本来就没有一条直接的记账通道。

*说明：本文讨论的是 AI 的单位经济，不讨论模型能力高低。文中的金额和比例是示意，用来展示结构，不是行业基准；不同业务的实际数字会差很远，但拆账的方法是一样的。*

![从 token 到利润，中间隔着四道漏斗](images/post-071/token-profit-funnel.svg)

先把结论放在前面：**Token 增长只发生在成本项，利润增长只发生在交付和定价项。中间隔着四道转化——有效推理、一次通过、被验收、能定价。大多数公司的 token 增长，只完成了第一道。**

这不是一篇劝你少用 AI 的文章。Token 花得多，可能正是业务在增长；真正要问的是，花出去的 token 有没有穿过后面三道门。

## 一、两张报表，两个真相

### 1. 一张是动作量，一张是结果量

AI 平台的报表很漂亮：调用量、token 数、活跃用户、平均延迟，每天都有曲线。财务的报表很冷静：收入、成本、毛利、净利，每个月才更新一次。

两边都没错，但它们量的不是同一种东西。

**Token 是动作量，利润是结果量。** 动作量可以无限增长，结果量不会自动跟随。一个人可以每天生成一百份方案，但如果只有三份被客户签字，剩下九十七份就是库存，不是收入。

更麻烦的是，token 账单精确、及时、按天可查；而 AI 带来的收益，往往散落在“员工说省了时间”“客户说体验更好了”“团队说质量提升了”这些无法直接入账的描述里。**成本是硬的，收益是软的；报表自然会显得难看。**

### 2. 先把公式写出来

把一笔 AI 生意拆到最小单位，其实只有四个变量：

```text
单件毛利 = 单件收入 − 单件推理成本 − 单件兜底成本
利润     = 验收交付量 × 单件毛利 − 固定成本
```

这里的“单件推理成本”已经把失败重试摊销进去了。Token 只出现在这一项里。它既不在收入项，也不在验收率里，更不自动等于交付量。

这意味着三件事：

- Token 涨，可能只是失败重试变多，交付量没变；
- 交付量涨，可能单价在跌，毛利还是没涨；
- 毛利涨了，可能固定成本涨得更快，净利润还是没动。

还要分清三种“没涨”：**毛利额没涨**（交付没增加，或单价在跌）、**毛利率没涨**（成本涨得比收入快）、**净利润没涨**（毛利被销售、研发、管理费用吃掉）。三种病，药完全不同。

所以“token 越烧越多，利润却没涨”不是一个问题，而是一组问题。**不把中间环节拆开，就只能在对账单上吵架。**

再补一个最容易被忽略的指标：

```text
有效 token 率 = 被验收交付所必需的 token / 总 token
```

大多数团队能准确说出这个月烧了多少 token，却说不清其中多少是“必需的”。如果有效 token 率只有 30%，那另外 70% 就不是在生产，而是在维持、试错和表演。

### 3. 三种 token 增长，只有一种可能健康

| 增长类型 | 典型信号 | 对利润的影响 |
| --- | --- | --- |
| 任务量增长 | 真实需求变多，交付量同步上升 | 可能健康，取决于单件毛利 |
| 使用深度增长 | 任务更复杂、上下文更长、推理更久 | 中性，取决于单价与成功率 |
| 空转增长 | 重试、重复生成、上下文重发、过度规划 | 纯成本，必须压掉 |

现实中的 token 账单通常是三者的混合。没有归因，就只能看到一个总数；看到一个总数，就只能做出“整体太贵”这种没有操作性的判断。

**第一个诊断问题不是“为什么 token 涨”，而是“涨的 token 属于哪一类”。**

## 二、Token 为什么容易越烧越多

先承认一个事实：单位 token 的价格，长期看一直在降。模型变小、推理变快、缓存变便宜、硬件变好，同等能力确实在变便宜。

但很多公司的总账单还是在涨。原因不神秘：**单价降一半，用量涨三倍，总成本还是涨 50%。** 这是杰文斯悖论在推理市场的版本——效率提高降低了单位成本，反而刺激了总消耗。

如果新增用量对应新增收入，这是好事；如果新增用量只是把原来免费的东西做得更贵，这就是坏事。下面五个结构性力量，决定了 token 很难“自然降下来”。

### 1. 上下文的复利：多轮不是加法，是乘法

多轮对话和 Agent 任务里，每一轮都要把历史上下文重新送进模型。上下文随轮次增长，账单就随轮次的平方增长。

```text
总输入 token ≈ n × 初始上下文 + 步长 × n(n−1)/2
```

举个具体的例子：一场 20 轮的会话，初始上下文 8k token，每轮新增 4k token。

- 最后一轮看到的上下文：8k + 19 × 4k = 84k；
- 整场会话实际计费的输入 token：Σ(8k + 4k × i) ≈ 920k。

**最后一轮只看到 84k，账单上却是 92 万。** 这还没算输出 token、工具调用和失败重试。

这就是为什么“长上下文”不是免费的内存，而是每轮都要重新付一次的租金。Prompt caching 能压低重复前缀的单价，但压不住上下文变长带来的新增消耗；缓存没命中时，账单还会更难看。

### 2. 思考税：推理模型把“多想一会儿”变成计费项

推理模型把 test-time compute 做成了产品：同一个问题，可以想 1 秒，也可以想 1 分钟。想得越久，token 越多，准确率通常会上升，但边际收益递减。

一个常见的曲线是：思考预算从低档拉到中档，准确率提升明显；从中档拉到高档，准确率只提升几个点，token 却翻几倍。**找到那个拐点，比无脑开最高档更值钱。**

模型升级也会悄悄提高默认消耗。系统提示更长、工具描述更多、默认开启推理、上下文窗口更大——单价可能降了 50%，单任务 token 却涨了 3 倍，账单还是涨。

### 3. 试错结构：成本是单价除以成功率

Agent 不是一次调用就结束的。它要规划、调工具、看结果、发现问题、重来。成本不能按“单价 × 次数”算，而要按“单价 ÷ 成功率”算：

```text
期望成本 = 单次尝试成本 / 成功率
```

成功率 50%，期望尝试 2 次；成功率 30%，期望尝试 3.3 次。如果失败后还要人来看一眼，成本就不是加法，是乘法。

**失败比成功更贵：它既烧 token，又烧人的注意力，还占用下游的评审资源。** 很多团队把预算花在“让 Agent 更敢做”上，却没有花在“让 Agent 更容易被验证”上，结果就是 token 越烧越多，交付越来越慢。

### 4. 使用面扩张：从试点到全员，从高价值到全场景

试点阶段的用户是自选的，任务是最适合 AI 的，上下文是干净的，失败是有人兜底的。全面推广之后，用户是全部的，任务是长尾的，上下文是脏的，失败是要算事故的。

这会出现一个很典型的错位：

- 用户数涨了 10 倍；
- 调用量涨了 30 倍；
- 平均每个任务的价值，反而降了；
- 但平均每个任务的成本，没有同比例下降。

如果收费方式是“按席位、不限量”，收入只随人数涨，成本却随用量涨。**采用曲线的斜率，往往快过定价模型的更新速度。**

### 5. 工作量通胀：token 变成了待评审的库存

AI 让生成变得便宜，人就会生成更多东西：更多草稿、更多版本、更多文档、更多测试、更多分析。问题是，评审、决策、整合的能力没有同步变便宜。

于是出现一种很奇怪的生产过剩：以前一个人一周写 2 份方案，现在一天生成 10 份；评审会从 1 小时变成 4 小时，交付周期一点没短。**AI 提高了产量，但没有提高吞吐量。**

按利特尔法则（Little's law），在制品（WIP）越多，平均流转时间越长。多出来的草稿不会自动变成利润，它们会先变成队列。Token 账单涨在这里，利润当然不会跟。

## 三、利润为什么没涨：五道断层

Token 增长本身不是罪。真正的问题是，增长出来的 token 没有穿过下面五道断层。

### 1. 会计断层：省下的是工时，花出去的是现金

人力成本是固定的：工资按月发，不会因为你这个月少写几份文档就自动下降。AI 成本是变动的：每调用一次，就多一笔支出。

这两件事在报表上的位置完全不同：

| 看到的变化 | 记在哪 | 是否等于利润 |
| --- | --- | --- |
| 员工每周省 5 小时 | 产能池 | 否，除非这些时间被卖掉 |
| 外包费减少 | 成本下降 | 是 |
| 编制冻结 | 成本避免 | 是，相对于预算 |
| Token 账单增加 | 运营成本 | 直接减利润 |

一个 100 人的团队，AI 让每个人省出 15% 的时间，相当于多出 15 个人的产能。但如果没有人被裁、没有外包被取消、没有新订单被接住，这 15 个人的产能就只是闲置。**财务看到的不是“省了 15 个人”，而是“多了一张 token 账单”。**

所以第一道断层很朴素：**工时节省是管理指标，减支才是财务指标。** 省下来的时间如果没有被重新安排到可交付的产出上，它就不是利润，只是更宽松的日程。

### 2. 系统断层：局部加速，撞上下游瓶颈

一个 10 天的交付周期，写作占 2 天，评审、测试、审批占 8 天。AI 把写作加速 5 倍，写作从 2 天降到 0.4 天，总周期变成 8.4 天。

**局部快了 5 倍，系统只快了 16%。**

用 Amdahl 定律写出来更清楚：

```text
总加速比 = 1 / ((1 − p) + p / s)
p = 被加速环节的占比，s = 该环节的加速倍数
```

p = 20%，s = 5，总加速比只有 1.19。省下的 1.6 天，被 8 天的下游吞掉了。

更糟的是，如果上游产出速度超过下游验收速度，队列会变长，交付周期可能不降反升。**AI 把瓶颈从“生产”移到了“验收”。**

这也是为什么很多 AI 项目在局部指标上非常漂亮，在利润上却毫无动静：**在非瓶颈环节提效，等于给堵车的高速路再加一个入口。** 约束理论讲得很直白：系统的产出由瓶颈决定，不提高瓶颈，其他环节再快也只是增加库存。

### 3. 竞争断层：效率红利被让渡给客户

如果一项能力所有竞争对手都能买到，它很快就会从“优势”变成“入场券”。

模型是公共基础设施。你能用，隔壁也能用；你接入了 Agent，隔壁下个月也能接入。当效率差距被抹平，竞争就会回到价格。你省下来的 20% 成本，可能在两个季度内变成 20% 的降价。

**在充分竞争的市场里，效率红利最终归客户，不归股东。** 想留住它，靠的不是“我们用了 AI”，而是模型之外的东西：专有数据、深度嵌入的工作流、切换成本、品牌信任、交付责任、分发渠道。

一句话：**模型是租来的，利润必须来自模型之外。** 如果你卖的东西和隔壁用同一个 API 做出来，客户唯一能比较的就是价格。

### 4. 定价断层：按席位收费，按 token 付成本

很多 AI 产品沿用了 SaaS 的定价：按月、按席位、不限量。这套模式在人工作业时代没问题，因为边际成本接近零；到了推理时代，边际成本不为零，而且重度用户和轻度用户的差距可能是几十倍。

| 定价方式 | 收入随用量 | 成本随用量 | 主要风险 |
| --- | --- | --- | --- |
| 席位订阅 + 不限量 | 否 | 是 | 重度用户侵蚀毛利 |
| 席位 + 额度包 | 部分 | 是 | 额度设计复杂，超额体验差 |
| 按 token 计费 | 是 | 是 | 价格透明，容易打价格战 |
| 按动作/结果计费 | 是（按结果） | 是 | 验收标准难定义，争议多 |
| 平台费 + 用量 + 结果 | 部分 | 是 | 复杂，但最接近价值 |

**按席位收费、按 token 付成本，本质上是把用量风险留给了自己。** 一个 5% 的重度用户，可能吃掉 50% 的推理预算；在产品端，这叫“用户增长”；在财务端，这叫“毛利稀释”。

还有一类更隐蔽的情况：AI 功能是免费送的，用来防守核心产品。成本进了销货成本（COGS），价格却没动。它可能是对的——用毛利买留存——但要清楚自己在买什么，而不是假装这笔成本不存在。

### 5. 长尾断层：简单的活被吃掉，难活留给人

自动化通常会先吃掉简单的、标准的、高频的任务。剩下的是例外、纠纷、高风险、需要判断的长尾。

客服 AI 解决了 70% 的简单工单，剩下 30% 是退款纠纷、投诉、法务风险。原来 10 个人的团队，可能只能减到 7 个人：剩下的人要处理更难的工单，还要审核 AI 的回复。**人均处理量下降了，单位成本反而上升。**

这背后是鲍莫尔成本病在 AI 时代的版本：越自动化的部分越便宜，越依赖人的部分越贵，最后拖住整体成本。**最后 10% 的准确率，往往要花 90% 的兜底成本。**

审查也是一样。审查一份 80 分的稿子，有时比写一份 60 分的稿子更累，因为你要逐句判断哪里对、哪里错、哪里看起来对但其实错了。**AI 把“生产”变便宜了，却把“验证”变贵了。**

## 四、把 token 账单翻译成损益表

### 1. Token 的五种经济性质

同样是 token，经济性质完全不同。先分类，再谈优化。

| 类型 | 典型来源 | 经济性质 | 该怎么管 |
| --- | --- | --- | --- |
| 交付 token | 直接生成被验收的产出 | 直接成本 | 按单件成本核算 |
| 探索 token | 方案搜索、假设验证、前期调研 | 研发/获客成本 | 设预算，按项目摊销 |
| 维持 token | 系统提示、历史重发、记忆、工具描述 | 运营开销 | 缓存、压缩、结构化状态 |
| 返工 token | 失败重试、重复生成、格式修正 | 质量成本 | 提高首次通过率 |
| 表演 token | 多 Agent 互评、过度规划、重复总结 | 纯浪费 | 删掉 |

“表演 token”不是讽刺所有多 Agent 设计，而是指那些**没有改变最终决策的消耗**：三个 Agent 互相 review，最后谁也没改；每轮都重新总结一遍已经总结过的内容；为一个二分类问题开三轮辩论。它们让流程看起来更智能，但不会让交付更好。

### 2. 六个必须看的指标

| 指标 | 算法 | 回答什么问题 |
| --- | --- | --- |
| 单件成功交付成本 | （推理 + 工具 + 人工兜底 + 返工）/ 验收交付数 | 每做成一件，到底花多少 |
| 首次通过率 | 一次验收通过数 / 总任务数 | 返工有多重 |
| 有效 token 率 | 必需 token / 总 token | 多少消耗在真正推进任务 |
| 人工兜底率 | 需人工介入的交付数 / 总交付数 | 自动化到底替代了多少人 |
| p95 单任务成本 | 95 分位单任务成本 | 长尾会不会吃掉预算 |
| Token 成本占收入比 | 推理成本 / 收入 | 毛利有没有被推理吃掉 |

有效 token 率最难精确，但可以用“最小可行 prompt”做对照估算，量级就够指导决策。平均值也会骗人：Agent 的成本分布是长尾的，p95 可能比均值高 5–10 倍。一个任务跑飞，就能吃掉一个月的预算。**只看平均 token，就像只看平均车速判断会不会出车祸。**

### 3. 一个算例：同样的 token，不同的利润

假设两个团队每月都烧 30M token，混合单价都是 ¥20/百万 token，推理成本都是 ¥600。差别在交付结构和人工兜底。

| | A：标准化交付 | B：定制化交付 |
| --- | --- | --- |
| 月 token | 30M | 30M |
| 推理成本 | ¥600 | ¥600 |
| 验收交付量 | 3,000 件 | 300 件 |
| 单件推理成本 | ¥0.2 | ¥2.0 |
| 单件人工复核 | 0.05 小时 × ¥300 = ¥15 | 1 小时 × ¥300 = ¥300 |
| 单件收入 | ¥30 | ¥200 |
| 单件毛利 | ¥14.8 | −¥102 |
| 毛利率 | 49% | −51% |
| 月毛利 | ¥44,400 | −¥30,600 |

两张账单的 token 成本都只有 ¥600，但一个赚 4.4 万，一个亏 3 万。**差别不在 token，在每件交付的人工和定价。**

这也是为什么“token 越烧越多，利润却没涨”有时是个伪问题：token 只是最显眼的那一行，真正漏水的可能是人工复核、返工、获客、或者价格。**盯着 token 降本，可能省下几百块，却放过几万块的结构性亏损。**

### 4. 一张 AI 增量损益表

把 AI 相关的变化单独拉出来，每个月算一次：

```text
AI 增量损益（月度）
+ 增量收入：新增订单、溢价、留存提升
+ 已实现减支：外包减少、编制冻结、采购下降
− 推理成本：输入 + 输出 + 重试 + 缓存未命中
− 工具与基础设施：向量库、沙箱、监控、存储
− 人工兜底：审核、修正、升级处理
− 返工与事故：赔付、合规、声誉
= AI 增量毛利
```

注意第二行：是“已实现减支”，不是“节省工时”。前者能进利润表，后者只能进产能池。

如果这张表是负的，不要用更多 token 去掩盖它。**先修单位经济，再放大总量。** 单位经济为负时，规模化只会把亏损放大得更快。

## 五、六条把 token 变成利润的动作

### 1. 先找瓶颈，再决定是否加 token

把交付流程画出来，标出每个环节的周期和队列。如果 AI 加速的不是瓶颈，就不要在那里加预算。

**在非瓶颈环节提效，产出不会增加，只会增加在制品。** 先把评审、验收、决策的吞吐量提上去，再给上游踩油门。

### 2. 把确定性搬出模型，把质量做在生成之前

能用规则、查表、缓存、检索、工作流解决的，不要用采样解决。**确定性是便宜的，推理是贵的。**

具体做法不复杂：

- 重复的任务用模板和结构化输出，不要让模型每次自由发挥；
- 稳定的事实用检索和数据库，不要塞进上下文让模型记；
- 能在生成前校验的，不要等生成后再返工；
- 能用小模型或规则分流的部分，不要全部交给最贵的模型。

把首次通过率从 60% 提到 80%，往往比把 token 单价砍一半更能改善利润。因为返工成本不只是 token，还有人的时间、队列和交付延迟。

### 3. 按成功交付核算，不按调用量核算

把 token 账单拆到产品、客户、任务类型，再除以对应的验收交付数。没有归因，就没有管理。

**不要问“这个月花了多少 token”，要问“这个月每个被验收的结果花了多少 token、多少人工、卖了多少价格”。** 如果一个团队说不清自己的单件成本，它还没有准备好规模化。

### 4. 给 Agent 装预算和刹车

Agent 需要的是预算，不是口号。至少设四道闸：

- 单任务最大 token；
- 单任务最大步数/工具调用次数；
- 单任务最大金额；
- 超过预算后的降级或升级策略。

再往前一步，是价值感知的算力分配：**先算这笔任务值多少钱，再决定用哪个模型、想多久、调几次工具。** 不是所有任务都配得上最贵的模型，也不是所有问题都值得想三分钟。

### 5. 重做定价，把用量风险传出去

不要卖无限量。至少要有额度包、超额计费、公平使用条款，或者按动作/结果计费。

定价的目标不是覆盖平均成本，而是覆盖 p95 成本和重度用户。**平均值定价，长尾买单；如果长尾是你自己，毛利就会替你买单。**

按结果收费听起来很美，但前提是验收标准清晰、争议处理有规则。否则省下的 token 成本，会变成客服和法务成本。

### 6. 把省下的产能卖掉

这是最容易被忽略的一条。AI 省下来的时间，不会自动变成利润。它只有三个去向：

1. 变成更多收入：接更多单、缩短交付周期、提高销售产能；
2. 变成更少成本：减少外包、冻结招聘、优化排班；
3. 变成闲置：更宽松的日程、更多的内部文档、更多的会。

前两个是利润，第三个是福利。**产能要么变成收入或减支，要么变成闲置，没有第三种结局。**

## 六、什么时候 token 增长是健康的

不是所有 token 增长都要压。早期探索、能力建设、数据飞轮，都可以短期亏。但要先过四道测验。

### 1. 四个测验

**边际测验：** 多花 ¥1 的 token，能不能带来超过 ¥1 的增量毛利？注意是毛利，不是收入。

**替代测验：** 它替代了哪一笔已经存在的预算？外包、人力、软件采购、广告获客。如果找不到被替代的预算，它大概率只是探索项目，应该设上限，而不是按“战略投入”无限续命。

**瓶颈测验：** 它加速的是不是系统的瓶颈？如果不是，省下来的时间会变成队列，不会变成利润。

**定价权测验：** 客户是否愿意为更好的结果多付钱？如果答案是否定的，效率提升最终会通过竞争让渡给客户。

### 2. 一张 2×2：增长不等于健康

![Token 增长与单件毛利：四种组合](images/post-071/token-growth-matrix.svg)

- **右上：健康规模化。** Token 涨，单件毛利也涨。可以踩油门。
- **右下：用利润买增长。** 交付变多，但每件越做越薄。需要有明确的规模效应或战略理由，否则越增长越危险。
- **左上：精益区。** 量不大，但每件都赚钱。可以慢慢找扩张路径。
- **左下：收缩区。** 量价齐跌，先止损，别谈规模化。

最危险的不是 token 涨，而是 **token 涨、单件成本涨、单件毛利跌**，同时团队还在说“我们在规模化”。那不是规模化，是漏损。

### 3. 亏损可以，但要有止损线

用亏损买学习曲线可以，用亏损买习惯不行。短期负毛利要满足三个条件：

- 有明确的止损线：烧到多少、烧到什么时候、达到什么指标就停；
- 有可验证的学习曲线：每次投入是否让单件成本下降、首次通过率上升；
- 有一条通往正毛利的路径：不是“等模型变便宜”，而是“我们具体做哪三件事让它变便宜”。

**“等 token 降价”不是战略，是祈祷。** 单价降了，用量可能涨得更快；真正能把单位经济做正的，还是流程、质量、定价和组织。

## 七、结语

Token 是 AI 时代的电费。

电费涨，不一定是因为工厂赚得多；也可能是因为机器空转、次品率高、或者产品卖不上价。你不能只看电表判断工厂的经营状况，同样，也不能只看 token 账单判断 AI 的 ROI。

AI 把“思考”变成了可计量的变动成本。这是好事：可计量就能管理。但它也把一个老问题放大了：**如果一家公司本来就算不清自己的单位经济，AI 只会让这件事更快、更贵地暴露出来。**

所以，下次看到 token 账单翻倍，先别急着问“怎么把 token 降下来”。先问四个问题：

1. 这些 token 里，多少变成了被验收的交付？
2. 每件交付的人工兜底和返工是多少？
3. 提效的环节是不是瓶颈？
4. 省下来的成本，是留在了公司，还是让给了客户？

四个问题答完，该降本降本，该提价提价，该停的项目停。

**利润不是烧出来的，是交付、验收、定价之后剩下的那部分。**
