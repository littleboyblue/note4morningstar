# 大模型不止一种：LLM、VLA、世界模型，各自在预测什么

> 「世界模型是不是视频生成模型的下一版？」「VLA 是不是多模态大模型加一条机械臂？」这两个问题我最近被问了不止一次。它们难回答，不是因为答案有多复杂，而是因为「大模型」这个词已经把四件不同的事混成了一件。这篇文章想做一件事：把常规 LLM、多模态模型、VLA、世界模型放进同一张坐标系，说清楚它们共享什么，又到底差在哪。

*说明：这是一篇概念梳理，不是新品盘点。文中提到的模型只作为某条路线的例子，具体指标以各自论文与官方文档为准；涉及数字的地方我标了量级和口径，跨品类的参数量我不做直接比较——那基本没有意义。*

![四类模型共享一套底座，但词表不同](images/post-070/model-taxonomy.svg)

## 一、先给一把尺子

### 1. 它们其实在做同一件事

不管哪一类，目标函数都能写成同一个形状：**在给定条件下建模一个分布，然后从里面采样。**

```text
LLM      L = -log p(x_t | x_<t)                     # x 是词
扩散模型  L = || ε - ε_θ(x_t, t, c) ||²              # x 是像素/帧
VLA      L = || a_t - π_θ(o_t, l) ||²                # a 是动作（或速度场）
世界模型  L = || z_{t+1} - f_θ(z_t, a_t) ||²         # z 是状态
```

四个式子长得像，是因为它们都在做「条件预测」。**不一样的是被预测的东西住在哪个空间里，以及预测出来之后有没有人去执行它。**

这句话是整篇文章的骨架。后面每一节，都只是在回答这两个问题。

### 2. 真正拉开差距的三件事

**第一，输出空间（词表）。** 语言是离散、低熵、有语法的；像素是连续、高维、多峰的；动作是连续、有时序、带物理约束的；世界状态则连「该用什么表示」都还没有共识。输出空间决定了三件事：能不能用交叉熵、能不能直接复用 Transformer、以及采样一次要多久。

**第二，监督信号（老师是谁）。** LLM 的老师是互联网文本，几乎免费；VLM 的老师是人类写的图文对和偏好；VLA 的老师是遥操作、真机试错和仿真；世界模型的老师是视频，但视频里没有动作标签——这是个致命细节，后面会讲。**一个品类的瓶颈，八成在数据，不在模型结构。**

**第三，是否闭环。** 写作、画图、生成视频，都是开环：输出错了，最坏结果是重来一次。机器人、自动驾驶是闭环：这一帧错了，下一帧的输入就建立在错误之上，误差会被系统放大。**开环任务可以容忍 90% 的准确率，闭环任务里 90% 意味着每十步摔一次。**

| 维度 | 它在问什么 | 四种答案 |
| --- | --- | --- |
| 输出空间 | 采样出来的东西是什么 | 词 / 像素 / 动作 / 隐状态 |
| 监督信号 | 老师从哪里来 | 互联网文本 / 人类偏好 / 遥操作与仿真 / 视频与物理约束 |
| 闭环 | 输出会被执行吗 | 不执行 / 人执行 / 机器执行 / 机器执行且不可回滚 |
| 错误代价 | 错一次的后果 | 重写 / 重画 / 重来一条 / 撞上去 |

把这四行填完，一个模型是什么、能干什么、不能干什么，基本就清楚了。下面逐类来。

## 二、常规大模型：把世界压进词表

### 1. 它到底在学什么

LLM 做的事情朴素到有点乏味：给定前文，预测下一个 token。训练目标是交叉熵，数据是几万亿到几十万亿 token 的文本，模型容量从几亿参数堆到上万亿（MoE）。

但这件事的效果好得违反直觉。原因不神秘：**要准确预测下一个词，模型被迫把语法、事实、推理套路、代码结构、甚至人类的说话习惯都压缩进权重里。** 压缩即理解——这是「下一 token 预测」最常被低估的地方。

从工程上看，今天的 LLM 已经不是「一个模型」，而是一条流水线：

| 阶段 | 干了什么 | 决定了什么 |
| --- | --- | --- |
| 预训练 | 在万亿 token 上做下一 token 预测 | 知识广度、语言能力、世界常识 |
| 指令微调（SFT） | 用几万到几百万条示范对齐格式 | 会不会「听话」 |
| 偏好对齐（RLHF/DPO） | 用人类偏好排序调分布 | 语气、有用性、拒答边界 |
| 可验证奖励强化（RLVR） | 用对错可判的题目做 RL | 数学、代码、长链条推理 |
| 后训练特化 | 工具调用、Agent 轨迹、长上下文 | 能不能「干活」 |

**注意最后两行。** 2024 年之后，模型能力的增量有相当一部分不是来自更大的基座，而是来自「怎么用后训练把基座逼出某种行为」。所谓「推理模型」「Agent 模型」，本质上都是同一块基座在不同奖励函数下的不同侧面——**它们不是新物种，是新性格。**

至于 GPT、Claude、Gemini、Qwen、DeepSeek 这些名字，它们都站在这一列里。差别在数据配比、后训练配方、推理成本和产品形态，而不在范式。

### 2. 它的三个天花板

**没有后果。** LLM 的输出不进入物理世界，所以它永远在「预测人类会怎么写」，而不是「验证事情会怎样」。这让它可以胡说得很流畅，也让它无法从自己行为的后果里学习。

**没有身体。** 「杯子在桌上」这句话，模型见过一百万次，但它没有「伸手去拿」这个动作的表征。所有关于空间、材质、力气的知识，都是二手的。

**评测正在饱和。** 主流 benchmark 的分数已经挤在高位，剩下的差距常常来自数据污染、prompt 敏感度和评测口径，而不是真实能力。**当一个榜的区分度低于它的噪声，这个榜就只剩公关价值。**

一句话总结：**LLM 是世界的文本投影，不是世界本身。** 它把「人类描述世界的方式」压得很好，但描述和操作之间隔着一整个物理世界。

## 三、多模态：给语言接上眼睛，或者给眼睛接上语言

「多模态」是个筐，至少装了两类完全不同的东西：**看得懂的**（VLM）和**画得出的**（生成模型）。它们的训练目标南辕北辙，却经常被同一个词打包。

### 1. VLM：把像素翻译成 token

主流做法分三代：

1. **双塔对比**（CLIP 系）：图像和文本各自编码，拉近匹配对、推远不匹配对。得到的是「对齐的向量空间」，不是「会说话的眼睛」。
2. **编码器 + 投影 + LLM**（LLaVA 系）：视觉编码器出 patch 特征，过一层 projector 变成若干「视觉 token」，塞进 LLM 的上下文里一起做下一 token 预测。
3. **原生早融合**：图像 patch 和文本 token 从第一层就混在一起，共享同一套注意力和位置编码。工程上更难，但少了「翻译损耗」。

这里有个很实际的工程变量：**视觉 token 预算**。一张 1024×1024 的图，按 14 像素一个 patch 切，就是 5300 多个 token；做 2×2 池化降到 1300，再狠一点降到 256。分辨率、细节、成本三者互斥——文档 OCR 要细，视频理解要省，没有通吃的配置。

VLM 的能力边界也很清楚：

- **描述强，指认弱。** 让它写一段图片说明很容易，让它准确说出「左边第三个红色按钮的坐标」很难。
- **计数和空间关系弱。** 这是视觉 token 化的结构性代价：patch 之间的几何关系在展平成一维序列时被稀释了。
- **时序理解更弱。** 视频不是「很多张图」，帧与帧之间的因果和动作连续性，需要额外的时序建模。

**它解决了「看见」，没解决「做到」。** 这句话是理解 VLA 的入口。

### 2. 生成模型：换一个损失函数，换一个世界

图像和视频生成走的是另一条路：不预测「下一个词」，而是学一个从噪声到数据的变换。

- **扩散模型**：从纯噪声出发，逐步去噪，每一步预测「噪声长什么样」。
- **流匹配 / Flow Matching**：学一个速度场，把噪声沿直线（或近似直线）推到数据分布，采样步数更少，训练更稳。今天主流的图像、视频、动作生成，很多都换到了这套。
- **自回归视觉生成**：先把图像量化成离散 visual token，再按语言模型的方式逐 token 生成。好处是能和多模态模型共用一套架构，坏处是 tokenizer 会丢细节。

为什么像素不能直接套 LLM 的交叉熵？三个原因：**连续**（没法做 softmax）、**高维**（256×256×3 的联合分布大到无法枚举）、**多峰**（一张图可以有很多合理解，用 L2 回归会得到一张模糊的平均图）。扩散和流匹配本质上是在绕开这三个问题。

### 3. 视频生成离世界模型有多远

这一两年最容易混淆的一句话是「视频模型就是世界模型」。判别标准其实不复杂，问四个问题：

1. **能被动作条件化吗？** 给它「向左转」这个指令，它生成的是左转后的画面，还是只是另一段好看的视频？
2. **能实时交互吗？** 你按一下键，它 100 毫秒内给出下一帧，还是一分钟后给你一段成品？
3. **有内部状态和记忆吗？** 镜头转回来时，桌上的杯子还在原来的位置吗？
4. **物理量守恒吗？** 水往低处流、刚体不穿模、光照方向和光源一致吗？

四个都答「是」，才是能拿来做决策的世界模型；只答得出「看起来像」，那是视频生成。**这两者的关系，类似「电影」和「飞行模拟器」——都能让你看到天空，但只有一个能用来练操作。**

## 四、VLA：当动作变成一种 token

### 1. 定义：输入图像和指令，输出动作

VLA = Vision-Language-Action。输入是相机图像（可能加本体状态）、自然语言指令，输出是机器人动作：末端执行器的位姿增量、关节角、夹爪开合，通常一次输出未来 H 步（action chunk）。

三种主流做法，代表三条不同的技术路线：

| 做法 | 怎么把动作接进来 | 代表 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| 离散动作 token | 每一维动作切成 256 个 bin，当成词表里的新词 | RT-2、OpenVLA | 完全复用 VLM 的下一 token 预测，工程最省 | 精度受量化限制，高频控制吃力 |
| 连续动作头 | 在 VLM 后面接 diffusion / flow matching 头，输出连续动作 | π0、RDT 系 | 动作平滑、多峰建模好、精度高 | 需要额外的动作专家，训练更复杂 |
| 快慢双系统 | 慢的 VLM 做语义与子任务，快的策略网络做反射 | Gemini Robotics、Helix 类 | 兼顾「想清楚」与「反应快」 | 两套系统要对齐，接口是新的故障点 |

第三种最像生物。**大脑想「去把桌上的杯子拿过来」，小脑负责每一毫秒怎么使力。** 让一个 7B 模型以 200Hz 输出关节角，既不经济也不现实；让它以 5Hz 决定「先绕过椅子」，再由一个小模型以 200Hz 执行，才是可落地的分工。

![VLA 的三层频率：慢思考、快执行、硬约束](images/post-070/vla-frequency.svg)

### 2. 为什么它比 LLM 难一个量级

**数据不存在。** 互联网上有一切文字，但没有「抓杯子时手腕该用多大力」的语料。VLA 的数据只能靠遥操作采集、真机试错、仿真合成，规模从 LLM 的 10¹³ token 掉到 10⁴–10⁶ 条轨迹。**这是硬约束，不是靠堆卡能解决的。**

**频率就是正确性。** 一个 50Hz 的控制回路，预算只有 20 毫秒。模型再大，推理延迟超过预算就是不能用。这也是为什么端侧量化、动作 chunk、双系统这些手段在 VLA 里格外重要——它们不是优化，是准入条件。

**跨本体是个未解题。** 同一个策略要能驱动六自由度机械臂、人形、灵巧手，就得把动作空间归一化到某种「共享表示」。目前的做法五花八门：末端位姿、关节角、latent action、甚至用视频预测当中间表示。**没有共识，说明这个领域还没到收敛期。**

**评测没有 ImageNet。** 真机成功率受场景、物体、初始位姿、光照影响，不同实验室的数字几乎不可比。你会看到「成功率 90%」和「成功率 40%」同时出现在同一任务上，区别只是测试集换了十件物体。

**错误不可回滚。** LLM 说错话可以道歉重说，机械臂把杯子摔了就是摔了。所以 VLA 系统必须有独立的安全层：力矩限幅、碰撞检测、工作空间约束、急停。**学习模型负责「聪明」，传统控制负责「不出事」，这个分工短期内不会消失。**

### 3. 现状：泛化在「任务族」，不在「任意任务」

公开演示里，VLA 已经能叠衣服、装盒子、煮咖啡、分拣零件。但仔细看，多数是在一个受控的任务族里泛化：换物体、换位置、换一点指令说法可以，换一个完全没见过的任务、换一套本体、换一种光照，成功率就掉得很快。

我的判断是：**VLA 现在的位置，类似 2018 年的 NLP——预训练 + 微调的范式已经成立，但「一个模型干所有事」还早。** 真正先落地的，会是那些任务边界清晰、失败代价可控、数据能自己闭环回收的场景：仓储分拣、产线上下料、实验室自动化。家庭场景最难，因为它的长尾几乎没有尽头。

## 五、世界模型：预测「如果我这样做，下一秒会怎样」

### 1. 三种东西都被叫世界模型

这个词现在被用得很松，至少指三件不同的事：

- **视频生成模型**：给定文本或首帧，生成一段逼真的视频。
- **动作条件的世界模型**：给定当前观测和一个动作，预测下一个观测（或状态）。
- **隐空间动力学模型**：不生成像素，只在表征空间里预测「下一步的状态向量」，供规划或强化学习使用。

三者的共同点只有一个：**它们都在预测「未来」**。区别在于预测的粒度、是否接受动作输入、以及预测结果给谁用。

### 2. 四个层级，从「像」到「能用」

![世界模型的四个层级](images/post-070/world-model-layers.svg)

从下往上看，越往上越接近「能拿来训练或评估策略」：

1. **视频生成**：追求视觉逼真，动作条件弱，不能实时交互。它能回答「这个镜头像不像」，不能回答「我这样做会怎样」。
2. **交互式世界模型**：接受动作输入、实时出帧、维持数分钟的场景一致性。它开始能当「神经游戏引擎」用，代表是 Genie 系列。
3. **隐空间世界模型**：不追求好看，只预测状态演化。JEPA 路线主张在表征空间预测、避免重建像素的浪费；Dreamer 系列用 RSSM 在隐空间里「想象」rollout，再拿去训练策略。
4. **显式 3D / 物理仿真**：几何、材质、碰撞、重力都是显式建模的，可验证、可微、可控。传统物理引擎和神经仿真（如 Cosmos 这类世界基础模型）都在这一层附近，一个偏规则，一个偏学习。

**这四层不是替代关系，而是工具箱里的四把工具。** 做内容用第一层，做交互 demo 用第二层，做策略训练用第三层，做工程验证用第四层。硬要一把锤子敲所有钉子，才是这个领域最常见的浪费。

### 3. 它到底拿来干什么

- **策略训练**：在「想象」里跑 rollout，比真机便宜几个数量级。Dreamer 4 在 Minecraft 里只靠离线数据学会玩，就是这条路线的标志性结果。
- **评估器**：真机测试又慢又贵，用世界模型做「如果这样开会不会撞」的前置筛选，能把实车/实机里程压缩。
- **规划**：Model Predictive Control 的老思路——用模型往前推演几步，选一条最好的走。世界模型只是把「模型」从物理方程换成了神经网络。
- **数据合成**：给自动驾驶造 corner case，给机器人造长尾场景。这是目前商业化最实在的用途。

### 4. 为什么它比视频生成难

**长时一致性。** 生成 10 秒很惊艳，生成 10 分钟就开始「忘记」：墙上的画换了、桌子的位置漂了、人物衣服变色。这不是分辨率问题，是记忆和状态管理问题。

**物理不是风格。** 视频模型可以学会「看起来像水」，但学不会「体积守恒」。而决策系统恰恰只关心守恒量。

**动作标签缺失。** 互联网视频里没有「当时按了哪个键」。所以动作条件的世界模型，要么靠游戏引擎/仿真器采数据，要么靠逆动力学模型从视频里反推动作——两条路都不便宜。

**评估标准缺失。** FVD、CLIP score 这些指标衡量的是「像不像」，不是「准不准」。**一个世界模型可以拿到很高的视觉分数，同时在物理上一塌糊涂。**

### 5. 和 VLA 的关系：一个是策略，一个是环境

这是最该讲清楚的一点。写成公式就一目了然：

```text
策略（VLA）      π(a | s, l)        —— 我该怎么做
世界模型         f(s' | s, a)       —— 如果我这么做，会变成什么样
```

VLA 是**策略**，世界模型是**环境**。把两者接起来，就是 model-based agent：在脑子里推演几种做法，选一个最好的再执行。**所以「VLA 和世界模型谁更重要」是个伪问题——它们是同一个系统的两半。**

也正因为如此，纯视频生成路线做不出好的控制策略：它能生成「机器人成功抓取」的视频，但那只是对结果的模仿，不是对因果的建模。**看起来会做，和知道怎么做，中间隔着动作条件化这一关。**

## 六、还有一整排「大模型」

上面四类是主线，但「大模型」这个词早就溢出了语言和机器人。下面这些同样是大规模预训练 + 一个明确输出空间，只是很少被放在一起讨论。

| 品类 | 输入 → 输出 | 训练信号 | 关键差异 |
| --- | --- | --- | --- |
| 语音识别/合成 | 波形 ↔ 文本 / codec token | 转写对齐、重建损失 | 流式、低延迟、说话人/情绪控制 |
| 全双工语音 | 音频流 → 音频流 | 对话数据 + 打断行为 | 延迟以百毫秒计，轮次管理是核心 |
| Embedding / 重排 | 文本 → 向量 / 相关性分数 | 对比学习（InfoNCE） | 不生成内容，只定义「相似」；评测看召回 |
| 代码与形式化 | 代码 / 证明状态 → 代码 / 证明步 | 下一 token + 编译器/证明器反馈 | 有可验证奖励，天然适合 RL |
| 科学模型 | 序列/结构/场 → 结构/场 | 几何等变损失、物理约束 | 数据少但先验强，评测靠实验验证 |
| 推荐模型 | 行为序列 → 下一个物品 | 下一物品预测 + 业务奖励 | 强闭环、强反馈回路，离线指标常骗人 |
| 时序/表格 | 历史序列/表格 → 未来值/预测 | 分位数损失、in-context 学习 | 样本少、可解释性要求高 |
| 自动驾驶 | 多相机/激光 → 轨迹/控制 | 模仿 + 轨迹损失 + 规则约束 | 本质是 VLA 的近亲，但动作是轨迹、安全约束极硬 |
| 3D 生成 | 图/文 → 网格 / 3DGS | 重建 + 对抗/扩散 | 输出要满足几何闭合、可渲染 |

看这张表会发现一件事：**每一类都在自己的「词表」上做条件预测，然后各自发明一套评测。** 所谓「通用大模型」，通用的是底座架构和训练范式，不是输出空间。

## 七、把它们放进一张表

这张表把「多模态」拆成了 VLM 和生成模型——它们只是共用一个名字，训练目标其实南辕北辙。

| 维度 | 常规 LLM | 多模态 VLM | 生成模型 | VLA | 世界模型 |
| --- | --- | --- | --- | --- | --- |
| 输入 | 文本 | 图 + 文 | 文 / 图 / 视频 | 图 + 指令 + 本体状态 | 观测 + 动作 |
| 输出 | 词 | 词（关于图） | 像素 / 帧 | 动作序列 | 下一状态 / 下一帧 |
| 损失 | 交叉熵 | 交叉熵 + 对比 | 去噪 / 流匹配 | 回归 / 流匹配 / 交叉熵 | 重建 / 隐空间预测 |
| 数据量级 | 10¹³ token | 10⁹ 图文对 | 10⁸–10⁹ 图、10⁶–10⁷ 视频 | 10⁴–10⁶ 轨迹 | 10⁶–10⁸ 视频 |
| 运行频率 | 事件驱动 | 1–10 Hz | 离线生成 | 10–100 Hz | 10–60 Hz |
| 闭环 | 否 | 否 | 否 | 是 | 否（但服务于闭环） |
| 评测 | benchmark | VQA / OCR / 定位 | FVD / 人工偏好 | 真机成功率 | 一致性 / 物理合理性 |
| 失败代价 | 重写 | 重问 | 重生成 | 撞、摔、伤人 | 策略学歪 |

四句话总结：

1. **LLM 预测词，VLM 把像素翻成词，生成模型预测像素，VLA 预测动作，世界模型预测状态。**
2. 越往右，数据越贵、评测越难；但真正闭环的只有 VLA 一列。
3. 参数量跨品类不可比——VLA 的 3B 可能比 LLM 的 300B 更难训。
4. **所有品类共享同一套底座，但没有任何一个能单独构成「智能」。**

## 八、五个容易踩的认知坑

**一、「多模态」不等于「能行动」。** 能描述「怎么拧螺丝」和能拧螺丝，中间隔着动作空间、频率、安全三层。VLM 是 VLA 的合理起点，但不是充分条件。

**二、「视频生成」不等于「世界模型」。** 判别标准就那四条：动作条件化、实时交互、状态记忆、物理守恒。缺一条，它就只是内容工具。

**三、「VLA 就是 LLM 加个机械臂」。** 动作的连续性和闭环的误差累积，会把你熟悉的 LLM 工程经验全部作废。这里没有「重试一次就好」。

**四、「参数量越大越强」。** 跨品类比参数，就像比一辆卡车和一架飞机的「马力」。数据、动作空间、闭环频率，任何一个都比参数量更能决定可用性。

**五、「一个模型全包」。** 一个 200Hz 的底层控制和一次 10 秒的语义规划，对模型大小、延迟、可验证性的要求是相反的。**融合会发生，但融合的形态是「分层 + 路由」，不是「一个巨型模型干所有事」。**

## 九、选型清单

| 你要解决的问题 | 先试哪类 | 关键前提 | 常见翻车点 |
| --- | --- | --- | --- |
| 写作、问答、代码、分析 | LLM（+ 检索/工具） | 输出可被人复核 | 把流畅当正确 |
| 看图质检、文档理解、监控描述 | VLM | 分辨率足够、目标不太小 | 视觉 token 被压太狠，细节丢失 |
| 出图、出视频、做素材 | 生成模型 | 版权、一致性、可编辑性 | 拿它当世界模型用 |
| 机械臂/人形执行固定任务族 | VLA + 传统控制兜底 | 有遥操作数据、有安全层 | 直接上开放环境，长尾打穿 |
| 训练机器人策略但真机太贵 | 世界模型 / 仿真 + sim2real | 仿真与现实的差距可测 | 只在仿真里刷分 |
| 自动驾驶感知与规划 | 端到端模型 + 规则约束 | 数据闭环、极端场景覆盖 | 用平均指标掩盖长尾 |
| 预测天气、分子、材料 | 专用科学模型 | 领域先验、实验验证 | 用通用 LLM 硬套 |
| 检索与推荐 | Embedding / 推荐模型 | 线上反馈闭环 | 离线指标涨、线上效果跌 |

一条通用建议：**先问「输出会不会被机器执行」，再问「错了能不能回滚」。** 两个答案都是「是」，才需要按闭环系统的标准去要求它——数据要覆盖长尾、延迟要卡死、安全层要独立。否则你只是在做一个更贵的生成器。

## 十、结语

回到最开始那两个问题。

「世界模型是不是视频生成模型的下一版？」——不是。视频生成解决的是「看起来真」，世界模型解决的是「推演得准」。前者是内容赛道，后者是决策基础设施。它们会互相借技术，但不是同一条演进线。

「VLA 是不是多模态大模型加一条机械臂？」——形式上是，本质不是。多模态模型学的是「人类怎么描述世界」，VLA 学的是「在这个世界里怎么做才有用」。后者需要动作、需要闭环、需要为错误负责。

而这四类模型放在一起，恰好拼出一个完整的智能系统该有的样子：**LLM 提供知识与语言，VLM 提供感知，世界模型提供想象与预演，VLA 提供执行。** 今天它们还是四个割裂的品类，各自有各自的 benchmark 和数据墙；但真正的产品，已经在把它们往一条流水线上焊。

所以与其问「下一个大模型是什么」，不如问一个更具体的问题：**我要它预测什么，预测出来给谁用，错了谁来兜底。** 这三个问题的答案，比任何榜单都更能决定你该选哪一类。
